# Pi audit, 26 Sept 2026

Raspberry Pi 4 Model B (4 GB), Debian 12 bookworm, kernel 6.1 (Nov 2023), Argon ONE case, Wi-Fi 5 GHz.

## Why it lags

**The microSD card does everything, and it is worn out.**

| | Measured | Healthy card on a Pi 4 |
|---|---|---|
| Sequential write | **9.4 MB/s** | 20–40 MB/s |
| 4K sync write | **213 kB/s (~50 IOPS)** | 1–3 MB/s |
| Sequential read | 39 MB/s | ~40 MB/s (bus limit) |
| Avg write latency (since boot) | **~540 ms** | < 20 ms |

- Card: Samsung EVO Plus 64 GB, **made 06/2018**, 479 GB written over its life, 81% full.
- OS, Docker, Plex database, logs and all torrents (35 GB) are on it. A torrent writes thousands of
  small random pieces: the worst possible load for an SD card. When the card stalls, everything
  waiting on disk stalls with it (SSH, web UI, Plex).
- Transmission write cache was 4 MB, so almost every piece hit the card directly.
- Kernel defaults let ~700 MB of writes pile up in RAM before flushing, which then freezes writers
  for seconds on a 9 MB/s card.
- A root cron rebooted the Pi **every day at 05:00**, probably added to cope with the freezes.
  It hides the problem and interrupts seeding.

CPU (idle 98%), RAM (3.4 GB free), temperature (44 °C), power (`throttled=0x0`) and Wi-Fi
(-18 dBm, 433 Mbit/s) are all fine. Wi-Fi power saving was on, which adds latency.

## Other findings

- **Ratio**: 0.00–0.23 on every torrent; 6 of 8 are stopped, and 3 have lost their files
  (deleted to free space). No space means no seeding means no ratio.
- Transmission credentials were committed in this public repo. They now live in `.env`
  (git-ignored): pick a new password.
- Plex had `privileged: true` (not needed, no hardware transcoding on Pi 4 in Plex), an empty
  `./media:/data` mount, and `ports:` blocks that Docker ignores with `network_mode: host`.
- 4.2 GB of unused Docker images (sonarr, radarr, jackett, bazarr, jellyfin, jellyseerr, old Plex).
- Leftovers in `~`: `testfile` (458 MB, root), `lucas-dock/`, `docker-compose/streaming-stack/`.
- 162 package updates pending (kernel from Nov 2023).
- Argon ONE fan software was not installed: the fan never ran. Reinstalled on 26 Sept
  (`argononed`, curve 55 °C→30%, 60 °C→55%, 65 °C→100%, `argon-config` to change it).

## What changed in this branch

- `docker-compose.yml`: one `DATA_DIR` for all media, single `/downloads` mount in Transmission
  (moves are instant renames), Plex transcoding in RAM, log rotation, credentials in `.env`,
  removed `privileged` / dead mounts / ignored ports.
- `scripts/tune-transmission.sh`: 64 MB cache, 2 downloads at a time, fewer peers, DHT/PEX/uTP off
  (private tracker), default destination `movies/`, stop each torrent once complete (no seeding).
- `scripts/tune-pi.sh`: Wi-Fi power save off, smaller write-back bursts, journal capped at 100 MB,
  bluetooth/ModemManager/triggerhappy off, daily reboot removed, timezone Paris, Docker cleanup.
- `scripts/status.sh` + `Makefile`: `make status | update | logs | restart`.
- `scripts/tune-plex.sh`: no video transcoding (unplayable files are refused), one conversion max,
  no chapter thumbnails / loudness / ad markers / deep analysis, scanner at low priority,
  debug logs off, 256 MB database cache.
- `scripts/install-argon.sh`: Argon ONE fan service without the installer's surprise upgrade.

## To do, by impact

1. **Replace the SD card** (worn out, 64 GB). Without seeding the card is idle once a download
   ends, so a new 128 GB A2 card is enough; a USB disk is the upgrade if the library grows.
2. `make tune`, then `sudo reboot`.
3. `sudo apt update && sudo apt full-upgrade`, then reboot.
4. Plug in Ethernet if the router is reachable (Wi-Fi is good, a cable is better for seeding).
5. Later: boot from a USB SSD and retire the SD card completely (the Pi 4 bootloader supports it).
